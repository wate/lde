インストラクション一覧
=========================

このドキュメントは、`.github/instructions/*.instructions.md` で定義された12件のインストラクションファイルを一覧化したものです。インストラクションとは、ファイル種別ごとに自動適用されるコーディング規約と品質基準であり、生成・編集時の判断を統一する役割を担います。規約を一元化することで、言語や用途をまたいだ品質のばらつきを抑制できます。

-------------------------

規約の適用ルール
-------------------------

### 適用優先順位

1. プロジェクト固有設定(例: `phpcs.xml`、`.prettierrc.yml`、`.yamllint.yml`)が最優先
2. ファイルパスに合致するインストラクションファイルの規約
3. 言語やフレームワークの標準規約(PSR、CakePHPフレームワーク規約等)

### 複数インストラクション重複時の扱い

以下の `applyTo` パターンが重複する組み合わせが存在します。

| ファイルパターン               | 重複するインストラクション                                   |
| ------------------------------ | ------------------------------------------------------------ |
| `src/Controller/**/*.php`      | `php.instructions.md` + `cakephp_controller.instructions.md` |
| `src/Model/**/*.php`           | `php.instructions.md` + `cakephp_model.instructions.md`      |
| `templates/**/*.php`           | `php.instructions.md` + `cakephp_view.instructions.md`       |
| `config/Migrations/**/*.php`   | `php.instructions.md` + `cakephp_migration.instructions.md`  |
| `**/*.md`                      | `markdown.instructions.md` + `japanese.instructions.md`      |
| `{.github/**/*.mjs,bin/*.mjs}` | `javascript.instructions.md` + `zx_script.instructions.md`   |

重複時の適用方針:

- **PHPファイル(`**/*.php`)がCakePHP固有パスに該当する場合**: PHP一般規約(`php.instructions.md`)を基底とし、CakePHP固有のインストラクション(controller/model/view/migration)で上書き・補完します。
- **Markdownファイル(`**/*.md`)**: `markdown.instructions.md` の構造ルールを基底とし、`japanese.instructions.md` の日本語表記ルールで補完します。
- `.mjs` ファイル(`.github/` または `bin/` 配下): `javascript.instructions.md` の一般JS規約を基底とし、`zx_script.instructions.md` のzx固有ルールで上書き・補完します。zxスクリプト以外の `.mjs` ファイルには `javascript.instructions.md` のみが適用されます。

規約サマリー
-------------------------

### `php.instructions.md` - PHP開発指針

- 目的: PHP開発コーディング規約・品質基準指針を適用する
- **主要ルール**:
    - インデントはスペース4文字、行長は通常160文字・絶対上限200文字
    - 配列は短縮構文 `[]` を使用し、`array()` は禁止
    - すべての関数・メソッドに日本語で `@param` / `@return` / `@throws` 付きDocコメント必須
    - PSR-4準拠の名前空間(ルート `App\`)とディレクトリ対応を維持
    - コード内SQLの予約語は大文字で記述
- 禁止事項:
    - 旧配列構文 `array()` の使用
    - タブインデント、CR/CRLF改行コードの使用
    - 除外対象外でのサイドエフェクトや名前空間なしクラス定義
    - 非UTF-8文字エンコーディング

### `javascript.instructions.md` - JavaScript開発指針

- 目的: JavaScriptファイルの一貫した記法と可読性を維持する
- **主要ルール**:
    - `import` / `export` 構文優先、CommonJSとの混在回避
    - 変数宣言は `const` 優先、再代入時のみ `let` を使用
    - 文字列は単一引用符、文末セミコロンは必須
    - すべての関数・メソッドに日本語でJSDoc記述(非エクスポート+単一式+自明な1行ヘルパーは省略可)
    - `.prettierrc.yml` に従って整形、1行120文字以内
- 禁止事項:
    - セミコロン省略
    - 二重引用符の常用
    - タブ文字インデント
    - CommonJSとES Modulesの混在
    - 未使用の変数・import・関数引数の放置
    - エクスポートされる関数または処理内容が自明でない関数のJSDoc省略

### `sql.instructions.md` - SQLファイル指針

- 目的: SQLファイルにおける統一されたコーディング規約と品質基準を定義する
- 主要ルール:
    - すべてのSQL予約語(SELECT, FROM, WHERE等)、データ型、関数名を大文字で記述
    - 4スペースインデント、主要キーワードは行先頭に配置
    - テーブルエイリアスは意味のある短縮形を使用
    - 複雑なサブクエリはCTE(`WITH`)の使用を検討
    - JOIN条件は明示的に `ON` 句で記述
- 禁止事項:
    - 予約語の小文字記述
    - タブ文字によるインデント
    - 暗黙的結合(カンマ結合)の使用
    - 意味のない単一文字エイリアスの常用

### `cakephp_controller.instructions.md` - CakePHP Controller実装指針

- 目的: CakePHPのController実装における画面遷移・フラッシュメッセージ・認可の規約
- 主要ルール:
    - 画面遷移パターン統一: `add`/`edit` は保存成功後に `view` へ、`delete`/ステータス変更は `index` へ、インポート/バッチは同一画面で結果表示
    - フラッシュメッセージは操作ごとに具体的な英語文言(msgid)を使用し、`default.po` に日本語訳追加
    - リソース操作アクションでは操作対象取得直後に `isAuthorized()` で所有権確認
    - 破壊的アクションは `$this->request->allowMethod(['post'])` でHTTPメソッド制限
    - Docコメントは日本語で記述
- 禁止事項:
    - bake既定のフラッシュ文言(`has been saved.`)をそのまま残すこと
    - リソース操作アクションでの所有権チェックの省略
    - 破壊的アクションをGETで実装すること
    - Controllerへのビジネスロジックの記述

### `cakephp_model.instructions.md` - CakePHP Model実装指針

- 目的: CakePHPのModel(Table・Entity・Enum)における実装規約とベストプラクティス
- **主要ルール**:
    - ステータスは `int` backed Enum + `EnumLabelInterface` で管理(caseの採番は間隔を空ける)
    - 再利用するクエリは `findXxx(SelectQuery $query): SelectQuery` としてカスタムファインダー定義
    - 表示判定や値の加工はEntityのメソッドとして集約し、Viewから条件分岐を排除
    - MariaDBの `meta` カラムは `$this->getSchema()->setColumnType('meta', 'json')` を `initialize()` で明示必須
    - bake再生成後は `setColumnType()` のEnum・meta型マッピングを手動で復元必須
- 禁止事項:
    - `Cake\Auth\*`(旧Authコンポーネント)の使用(CakePHP 5で削除済み)
    - ステータス等を生の整数リテラルで比較・代入(必ずEnumのcaseを使用)
    - Viewで参照する値をEntityの外(Controller・View)で複雑加工

### `cakephp_view.instructions.md` - CakePHPビューファイル指針

- 目的: CakePHPのビューファイルにおける推奨されるコーディング規約とベストプラクティス
- 主要ルール:
    - PHP代替構文(`if-endif` 等)を使用せず標準PHP構文(中括弧 `{}`)を使用
    - 状態表示のバッジ色・ラベル等の判定ロジックはビューヘルパーに委譲
    - 単一タグはヘルパー、複数タグ構造はエレメント、複雑な表示ロジックはビューセルに切り出し
    - ビュー内ロジックは簡単な条件判定・ループのみに制限
    - データ存在チェック(`empty()` / `isset()`)を省略せず未定義変数出力を防止
- 禁止事項:
    - PHP代替構文(`if-endif`、`foreach-endforeach`、`switch-endswitch` 等)の使用
    - ビュー内でのデータベースクエリ実行や複雑な計算処理
    - 状態表示(バッジ色等)の判定ロジックをビューやエレメントに直接記述
    - セッションやクッキーの直接操作
    - データ存在チェックなしでの変数出力

### `cakephp_migration.instructions.md` - CakePHP マイグレーション実装指針

- 目的: CakePHP/migrationsによるマイグレーションファイルの作成規約とベストプラクティス
- **主要ルール**:
    - `declare(strict_types=1)` + `change()` メソッドで定義
    - ベースクラスはプロジェクト実物に合わせる(Phinx依存世代 `Migrations\AbstractMigration` と非依存世代 `Migrations\BaseMigration` を確認)
    - テーブル・カラムに日本語 `comment` を必須付与
    - ステータス列の `comment` に `[enum] ラベル=値, ...` 形式でEnumマッピングを記載
    - 主要業務テーブルに予備カラム `meta` をJSON型で付与可能(中間テーブル・ログ・単純マスタには付与しない)
- 禁止事項:
    - 適用済み(migrate済み)のマイグレーションファイルを編集すること
    - `comment` のないテーブル・カラムを追加すること
    - ステータス列の `comment` にEnumマッピングを書き忘れること
    - ベースクラス・`use` をプロジェクトのバージョンと食い違わせること

### `markdown.instructions.md` - Markdownファイル作成指針

- 目的: Markdown文書の構造整合性と可読性を担保する
- **主要ルール**:
    - h1は文書内1つのみ、見出しレベルは1段ずつ増加
    - h1は `===`、h2は `---`(Setext形式)、h3以上は `###`(ATX形式)で記述
    - 見出し前後に空行を1行入れる
    - 太字使用は `**注意**:` / `**警告**:` / `**重要**:` の接頭辞と意味解釈に必要な語句強調(1文1箇所まで)に限定
    - ネストリストのインデントは4スペースで統一
    - 実在パス・固有名詞は必ずインラインコード(バッククォート)で囲む
- 禁止事項:
    - タブ文字の使用
    - 見出しレベルのスキップ(h1→h3等)
    - h1見出しの複数使用や太字による見出し代用
    - 文末・段落末尾のコロン使用
    - リスト項目名の太字装飾
    - AI特有の表現(「見ていきましょう」「いかがでしたか」等)

### `japanese.instructions.md` - 日本語文書作成指針

- 目的: 日本語文書作成・品質基準指針を適用する
- 主要ルール:
    - 基本はですます調、同一リスト内で体言止めと動詞文を混在させない
    - 一文100文字以内、長文は句点で区切り箇条書きへ分解
    - 半角英数字と全角文字の間は原則スペース禁止
    - 副詞・形式名詞・補助動詞は原則ひらがな(例: さらに→さらに、〜してください→〜してください)
    - カタカナ語は続け書き原則、外来語は長音記号省略なし
- 禁止事項:
    - 文体の混在
    - 全角数字の使用
    - 全角括弧や全角記号(`（）` `＜＞` `：` `／` 等)の使用
    - 絵文字や装飾記号(`✓` `✗` 等)の使用
    - 不要なスペースの挿入
    - 略語や固有名詞の表記ゆれ

### `yaml.instructions.md` - YAMLファイル作成指針

- 目的: YAMLファイルの一貫した記法と可読性を維持する
- 主要ルール:
    - インデントはスペース2文字で統一
    - 同一階層でキー名重複禁止、インライン記法 `{}` / `[]` 内のスペースは最小限
    - 真偽値は `true` / `false`
    - 意味的なセクション区切り以外では不要な空行を挿入しない
    - YAML 1.2準拠、`.yamllint.yml` 設定への適合
- 禁止事項:
    - タブ文字によるインデント
    - 同一階層の項目間への過剰な空行挿入
    - 重複キーの定義
    - 暗黙的な8進数として解釈される数値表現(先頭 `0` の数値)

### `d2.instructions.md` - D2言語図表ファイル指針

- 目的: D2言語による図表ファイルの一貫した品質を担保する
- **主要ルール**:
    - 冒頭にコメントでタイトルと目的を必須記載
    - `vars` ブロックでd2-config(レイアウトエンジン、テーマ)を定義
    - `classes` を活用して個別ノードへの直接スタイル設定を回避
    - 2スペースインデント、セクション間1行空行、単一行コメント(`#`)のみ使用
    - 図表タイプ別品質基準: シーケンス図は時系列正確性、画面遷移図は全画面網羅性、状態遷移図は状態の完全性
- 禁止事項:
    - ブロックコメントの使用
    - シーケンス図での時系列混乱(メッセージフローが時系列順でない)
    - 画面遷移図での孤立画面
    - 状態遷移図での到達不可能/抜け出せない状態

### `zx_script.instructions.md` - zxスクリプト開発指針

- 目的: zxスクリプトの安全で一貫した実装を確保する
- 主要ルール:
    - ファイル先頭に `#!/usr/bin/env zx` を付与
    - シェルコマンドはzxの `$` テンプレートタグで実行
    - 変数展開は `${}` 補間のみ使用し、文字列結合によるコマンド構築は禁止
    - 外部からの入力値は必ず `$` テンプレートタグの補間で渡す(シェルインジェクション防止)
    - JavaScript用インストラクション(`javascript.instructions.md`)と併用
- 禁止事項:
    - `#!/usr/bin/env zx` の省略
    - シェルコマンドの文字列フォーマット(`$('cmd ' + variable)` 等)での実行
    - `exec` や `spawn` などNode.js標準APIを直接使用してシェルコマンドを実行すること

まとめ
-------------------------

インストラクションは、ファイル種別ごとに自動適用される規約であり、プロジェクト全体の品質基準を統一します。PHPやJavaScript等の言語系、MarkdownやYAML等のマークアップ系、zxスクリプト等のスクリプト系に大別され、CakePHP関連のインストラクションはより具体的なファイルパスに適用されます。`applyTo` パターンが重複する範囲では、より具体的なほうの規約を優先しつつ共通規約で補完する運用で、一貫性と柔軟性を両立できます。
