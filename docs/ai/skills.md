使い分けの指針
-------------------------

### 利用シーン別の選択戦略

- 要件が曖昧な開始時: `hearing` を優先して目的と制約を明確化します。
- 計画が必要な場合: `workplan` で作業をWBS分解し、実行可能なタスク構造にします。
- 品質確認が必要な場合: `review` で成果物を5段階重要度で評価します。
- ドキュメント・コードの点検: `check-document`(ドキュメント品質)、`check-fact`(事実)、`check-code`(コード)、`refine`(記述の詰め)を使い分けます。
- データ分析・変換: `duckdb` で大規模データを処理し、`excel` で帳票を出力します。
- 画像制作: `graphic-creator` で新規生成、`image-manipulator` で既存画像を加工します。

### ワークフロー型スキルの連鎖

上位のワークフロースキルは、実行フェーズに応じて下位スキルを連鎖的に読み込みます。

- スライド制作: `slide-workflow` -> `hearing` / `slide-structure` / `design-token` / `pptx`
- Webサイト制作: `website-workflow` -> `screen-flow` / `design-token` / `ui-pattern` / `mockup`

### セキュリティ・コンプライアンス対応

- 脆弱性スキャン: `osv-scanner` で依存関係全体を把握 -> 必要なCVEのみ `cve-analyzer` で深掘り
- 法令確認: `e-gov` で日本の法令を検索・取得し、コンプライアンス検証
- EOL確認: `endoflife` で使用製品のサポート終了日を確認
- 補助金調査: `jgrants` で補助金・助成金情報を検索

### 運用継続での履歴管理

`review` で指摘を整理 -> `feedback` で判断軸と経緯を保存 -> `handoff` で次回再開情報を引き継ぐ、の順序で運用します。

効率化のポイント
-------------------------

### 探索系と実行系の分離

調査・探索系(`web-search`、`lindera` 等)と実行・実装系(`zx`、UI系スキル等)を分けて使うと、不要なスキル読み込みを減らせます。

### user-invocable スキルの活用

以下のスキルはユーザーから明示的に呼び出せます(`user-invocable`が`true`または未指定)。要件に応じて直接指定してください。

- `agent-creator`・`agent-guide`・`agent-skill-creator`・`annotate-code`・`api-spec`・`business-flow`
- `check-code`・`check-document`・`check-fact`・`d2`・`database-design`・`design-token`・`drawio`
- `feedback`・`generate-spec`・`glossary`・`graphic-creator`・`handoff`・`hearing-sheet`
- `image-manipulator`・`infrastructure`・`md-links`・`operation-design`・`persona`・`pict`
- `problem-analysis`・`project-docs`・`project-overview`・`prompt-creator`・`proposal`・`refine`

- `website-workflow`・`workplan`・`zensical`

### ワークフロースキル起点の選択

新規作成系の作業は、上位のワークフロースキル(`slide-workflow`、`website-workflow`)を起点にすると、必要な下位スキルが自動連鎖的に読み込まれます。
