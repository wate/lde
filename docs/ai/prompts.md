カスタムプロンプト一覧
=========================

このドキュメントは、ワークスペースで利用可能なカスタムプロンプト(`.github/prompts/*.prompt.md`)を用途別に整理した一覧です。
各プロンプトの「できること」「主な入力」「主な出力」を確認し、目的に合ったプロンプトを選択できます。

使い分けの指針
-------------------------

### 近い用途のプロンプト間の選択基準

- `doc-*`, `design-*`, `d2-*`, `drawio-*`の使い分け
    - `doc-*`: 文章形式のドキュメントを作成(仕様書、手順書、一覧等)
    - `design-*`: 設計書や設計基準を作成(データベース設計、インフラ設計、UI設計)
    - `d2-*`: D2言語で図表を作成(画面遷移図、シーケンス図、アクティビティ図)
    - `drawio-*`: Draw.io XML形式で図表を作成(ER図、スイムレーン図)
- `check-*`プロンプトの使い分け
    - `check-code`: コードレビュー全般(変更差分が対象)
    - `check-markdown`: Markdown記法と日本語表記のチェックに特化
    - `check-fact`: 内容の事実正確性・最新性の検証
    - `check-document`: 読者適合性(表現レベル・用語)の評価
    - `check-prompt` / `check-agent` / `check-instruction` / `check-skill`: AI協業フレームワーク構成要素の品質チェック
    - `check-guideline`: 任意のガイドラインに対する汎用準拠チェック
- `check-*`と`refine-precision`の使い分け
    - `check-*`: 問題を検出・報告する(成果物は変更しない)
    - `refine-precision`: 問題を検出し、機械的に改善できる箇所は直接編集で反映する(成果物を変更する)
- 生成系プロンプトの使い分け
    - `generate-agent` / `generate-instructions` / `generate-prompt` / `generate-skill`: AI協業フレームワークの構成要素を新規作成
    - `generate-testcase` / `generate-usecase`: テスト設計(テストケース詳細vsユースケース列挙)
    - `generate-spec`: 既存コードから仕様書をリバース生成
- 派生プロンプトの関係
    - `proposal-risk` / `proposal-kpi` は `doc-proposal` の派生(改善提案の補完分析)
    - `task-visualize` / `task-convert_csv` は `task-generate_tasklist` の派生(タスクリストの後処理)

### プレフィックス別の出力先傾向

| プレフィックス                      | 主な出力先                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------------- |
| `doc-`, `design-`, `d2-`, `drawio-` | `docs/` 配下                                                                 |
| `generate-`                         | `.github/` 配下(エージェント・インストラクション・スキル)または `docs/` 配下 |
| `check-`                            | 基本的に会話内出力(確認用)                                                   |
| `report-`                           | プロジェクトルート(永続化は `logs/` も可)                                    |
| `infra-`                            | プロジェクトルートまたは `docs/` 配下                                        |

### チェック系プロンプトの出力先

チェック系(`check-*`)の大部分は会話内で結果を出力します。
`check-guideline` のみ状況に応じてファイル出力も可能です。

効率化のポイント
-------------------------

### プレフィックス活用による目的の絞り込み

カスタムプロンプトはファイル名のプレフィックスで用途が分類されています。
目的に応じて以下のプレフィックスで絞り込むと効率的です。

| プレフィックス | 用途                             |
| -------------- | -------------------------------- |
| `doc-`         | ドキュメント作成・更新           |
| `check-`       | 品質チェック・レビュー           |
| `design-`      | 設計書作成                       |
| `d2-`          | D2図表作成                       |
| `drawio-`      | Draw.io図表作成                  |
| `generate-`    | AI協業構成要素やテスト資材の生成 |
| `task-`        | タスク管理                       |
| `issue-`       | 課題管理・チケット処理           |
| `report-`      | レポート生成                     |
| `infra-`       | インフラ構成管理                 |
| `proposal-`    | 提案分析                         |
| `scan-`        | セキュリティスキャン             |
| `review-`      | レビュー実行                     |

### 派生プロンプトの見分け方

ベースプロンプトから派生した専門処理用プロンプトは、
ファイル名が `{ベース名}-{専門処理名}.prompt.md` の形式になっています。
同じプレフィックスグループ内で補完関係を把握する際の参考にしてください。

#### 例

- `doc-proposal` → `proposal-risk`、`proposal-kpi`
- `task-generate_tasklist` → `task-visualize`、`task-convert_csv`

### 品質チェックの流れ

特定の構成要素(プロンプト・エージェント・インストラクション・スキル)を新規作成した際は、対応する `check-*` プロンプトで品質を確認すると、一貫性と品質を担保できます。

### ワークフロー連携例

- `doc-problem` → `doc-proposal` → `doc-requirements` → `doc-rest_api` / `design-database`: 問題分析から設計までの一貫チェーン
- `scan-vulnerability` → `report-vulnerability`: 脆弱性スキャンからトリアージレポートまで
- `generate-prompt` → `check-prompt`: プロンプト作成から品質確認まで
- `infra-hearing` → `infra-terraform`: 要件構造化からコード生成まで
- `design-ui_layout` → `doc-ui_pattern`: UIレイアウト確定から画面単位の仕様書作成まで

まとめ
-------------------------

本プロジェクトには74件のカスタムプロンプトが用意されており、ドキュメント生成・品質チェック・設計・図表作成・タスク管理・レポート生成・インフラ運用など多岐にわたる作業をカバーしています。
プレフィックスによる目的分類と出力先の傾向を把握することで、目的のプロンプトを素早く見つけられます。
また、派生プロンプトの関係性やチェック系プロンプトとの組み合わせを活用することで、
一貫性のある成果物生成と品質保証のサイクルを効率的に回せます。
