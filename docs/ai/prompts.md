カスタムプロンプト一覧
=========================

このドキュメントは、ワークスペースで利用可能なカスタムプロンプト(`.github/prompts/*.prompt.md`)を用途別に整理した一覧です。
各プロンプトの「できること」「主な入力」「主な出力」を確認し、目的に合ったプロンプトを選択できます。

利用シーン別プロンプト一覧
--------------------------

### 注意事項

多数のカスタムプロンプトは使い分けが難しいため、スキルへの移行および統合を進めています。  
カスタムプロンプトは明示的な呼び出しが必要ですが、  
スキルはそれに加えて発動条件の記述による自動発動にも対応できるためです。  
移行先のスキルは[スキル一覧](skills.md)にまとめています。

### ドキュメント生成系

ドキュメントを作成・更新するプロンプト群です。

| 呼び出し名       | できること                                        | 主な入力                      | 主な出力             |
| ---------------- | ------------------------------------------------- | ----------------------------- | -------------------- |
| `doc-deployment` | Ansibleプレイブックを解析し、デプロイ手順書を生成 | `deploy.yml`、`inventory.yml` | `docs/deployment.md` |

### 各種生成系

AI協業フレームワークの構成要素やテスト資材を生成するプロンプト群です。

| 呼び出し名       | できること                                                     | 主な入力                           | 主な出力                           |
| ---------------- | -------------------------------------------------------------- | ---------------------------------- | ---------------------------------- |
| `generate-agent` | カスタムエージェントを設計・作成し、役割定義と責務範囲を明確化 | エージェントの目的、専門領域、責務 | `.github/agents/{職種名}.agent.md` |

### コード補助・テスト系

コード品質向上やテスト設計を支援するプロンプト群です。

| 呼び出し名         | できること                                                                 | 主な入力                             | 主な出力                                                             |
| ------------------ | -------------------------------------------------------------------------- | ------------------------------------ | -------------------------------------------------------------------- |
| `extract-urls`     | WebページからURLを抽出しMarkdown形式でリスト化                             | 対象WebページのURL                   | プロジェクトルートまたは指定ディレクトリ                             |
| `testcase-fixture` | テストケースからデータ要件を抽出し、スキーマに基づくYAMLフィクスチャを生成 | テストケースドキュメント、DBスキーマ | `config/Seeds/data/scenarios/`(CakePHP)または `docs/testcase/`(汎用) |

使い分けの指針
-------------------------

### 近い用途のプロンプト・スキル間の選択基準

- コードレビュー
    - `check-code`スキルを使います(既定は変更差分が対象です)。
- AI資産の品質チェック
    - 対象はプロンプト、エージェント、インストラクション、スキルです。
    - `review`スキルで、資産の種類に応じた品質チェックリストへ照合します。
- AI資産の作成
    - `generate-agent`: カスタムエージェントを新規作成します。
    - `agent-skill-creator`スキル: スキルと`/`コマンドから呼び出すラッパーを新規作成します。
    - `prompt-creator`スキル: Webチャットへ貼り付ける単発プロンプトを新規作成します。
- スキルへ移行済みの作業
    - 問題分析: `problem-analysis`スキル
    - 改善提案(KPI設定・リスク評価を含む): `proposal`スキル
    - 要件定義: `requirements`スキル
    - 業務フロー: `business-flow`スキル
    - ペルソナ: `persona`スキル
    - テストケース設計: `testcase`スキル
    - ユースケース列挙: `usecase`スキル
    - タスクリストの作成と後処理(可視化・issue化・CSV変換): `tasklist`スキル
    - 要確認事項への方針提案: `unresolved-proposal`スキル
    - 複数の視点でのレビュー: `review`スキル
    - ヒアリングシートの作成: `hearing-sheet`スキル
    - API仕様書(OpenAPI): `api-spec`スキル
    - データベース設計: `database-design`スキル
    - 運用設計: `operation-design`スキル
    - インフラの構成選定・要件定義・Terraformのコード・Ansibleの変数: `infrastructure`スキル
    - デザインシステム・UIデザイン資料・UIパターン設計書: `ui-docs`スキル
    - コードのアノテーション(Docコメント)の追加・改善: `annotate-code`スキル

### プレフィックス別の用途と出力先

| プレフィックス | 用途                   | 主な出力先            |
| -------------- | ---------------------- | --------------------- |
| `doc-`         | ドキュメント作成・更新 | `docs/`配下           |
| `generate-`    | エージェントの生成     | `.github/agents/`配下 |

`extract-urls`、`testcase-fixture`は接頭辞を持たない単発のプロンプトです。

効率化のポイント
-------------------------

### 品質チェックの流れ

AI資産を新規作成した際は、資産の種類に応じた品質チェックリストへ照合します。
照合により、一貫性と品質を担保できます。
チェックリストの参照先と評価フレームは`review`スキルの`references/ai_assets.md`に整理されています。

### ワークフロー連携例

- `problem-analysis` -> `proposal` -> `requirements` -> `api-spec` / `database-design`: 問題分析から設計まで
- `osv-scanner`スキル -> `vulnerability-triage`スキル: 脆弱性スキャンからトリアージレポートまで
- `prompt-creator`スキル -> `review`スキル: プロンプト作成から品質確認まで
- `infrastructure`スキル: 構成選定 -> 要件定義 -> Terraformのコード -> Ansibleの変数の順に、前の成果物を入力にして進めます

まとめ
-------------------------

本プロジェクトには4件のカスタムプロンプトが用意されています。
主要な文書作成と品質チェックはスキルへ移行済みで、プロンプトはデプロイ手順書・エージェントの生成など、まだスキルへ移行していない作業に使います。
プレフィックスによる用途分類と出力先の傾向を把握すると、目的のプロンプトを素早く見つけられます。
スキルと組み合わせる場合は[スキル一覧](skills.md)を参照してください。
