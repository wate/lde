カスタムプロンプト一覧
=========================

このドキュメントは、ワークスペースで利用可能なカスタムプロンプト(`.github/prompts/*.prompt.md`)を用途別に整理した一覧です。
各プロンプトの「できること」「主な入力」「主な出力」を確認し、目的に合ったプロンプトを選択できます。

利用シーン別プロンプト一覧
--------------------------

### 注意事項

多数のカスタムプロンプトは使い分けが難しいため、スキルへの移行および統合を進めています。  
カスタムプロンプトは明示的な呼び出しが必要ですが、  
スキルはそれに加えて発動条件の記述による自動発動にも対応できるためです。  
移行先のスキルは[スキル一覧](skills.md)にまとめています。

使い分けの指針
-------------------------

### 近い用途のプロンプト間の選択基準

- `doc-*`, `design-*`の使い分け
    - `doc-*`: 文章形式のドキュメントを作成(仕様書、手順書、一覧等)
    - `design-*`: 設計書や設計基準を作成(データベース設計、インフラ設計、UI設計)
- コードレビュー
    - `check-code`スキルを使います(既定は変更差分が対象)。
- AI資産の品質チェック
    - 対象はプロンプト、エージェント、インストラクション、スキルです。
    - 該当する品質チェックリストを`review`スキルで評価します。
- 生成系プロンプトの使い分け
    - `generate-agent`: カスタムエージェントを新規作成
    - `prompt-creator`スキル: Webチャットへ貼り付ける単発のプロンプトを新規作成
    - `agent-skill-creator`スキル: スキルと、`/`コマンドから呼び出すラッパーを新規作成
    - テストケースの設計(`testcase`スキル)とユースケースの列挙(`usecase`スキル)は、スキルへ移行済み
- 派生プロンプトの関係
    - `proposal-risk` / `proposal-kpi` は `doc-proposal` の派生(改善提案の補完分析)
    - `task-visualize` / `task-convert_csv` は `task-generate_tasklist` の派生(タスクリストの後処理)

### プレフィックス別の出力先傾向

| プレフィックス    | 主な出力先                                                                   |
| ----------------- | ---------------------------------------------------------------------------- |
| `doc-`, `design-` | `docs/` 配下                                                                 |
| `generate-`       | `.github/` 配下(エージェント・インストラクション・スキル)または `docs/` 配下 |
| `check-`          | 基本的に会話内出力(確認用)                                                   |
| `report-`         | プロジェクトルート(永続化は `logs/` も可)                                    |
| `infra-`          | プロジェクトルートまたは `docs/` 配下                                        |

効率化のポイント
-------------------------

### プレフィックス活用による目的の絞り込み

カスタムプロンプトはファイル名のプレフィックスで用途が分類されています。
目的に応じて以下のプレフィックスで絞り込むと効率的です。

| プレフィックス | 用途                             |
| -------------- | -------------------------------- |
| `doc-`         | ドキュメント作成・更新           |
| `check-`       | 品質チェック・レビュー           |
| `design-`      | 設計書作成                       |
| `generate-`    | AI協業構成要素やテスト資材の生成 |
| `task-`        | タスク管理                       |
| `issue-`       | 課題管理・チケット処理           |
| `report-`      | レポート生成                     |
| `infra-`       | インフラ構成管理                 |
| `proposal-`    | 提案分析                         |
| `review-`      | レビュー実行                     |

### 派生プロンプトの見分け方

ベースプロンプトから派生した専門処理用プロンプトは、
ファイル名が `{ベース名}-{専門処理名}.prompt.md` の形式になっています。
同じプレフィックスグループ内で補完関係を把握する際の参考にしてください。

#### 例

- `doc-proposal` -> `proposal-risk`、`proposal-kpi`
- `task-generate_tasklist` -> `task-visualize`、`task-convert_csv`

### 品質チェックの流れ

特定の構成要素(プロンプト・エージェント・インストラクション・スキル)を新規作成した際は、該当する品質チェックリストへ照合します。
照合により、一貫性と品質を担保できます。
評価フレームは`review`スキルを利用できます。

### ワークフロー連携例

- `doc-problem` -> `doc-proposal` -> `doc-requirements` -> `doc-rest_api` / `design-database`: 問題分析から設計までの一貫チェーン
- `osv-scanner`スキル -> `vulnerability-triage`スキル: 脆弱性スキャンからトリアージレポートまで
- `prompt-creator`スキル -> `review`スキル: プロンプト作成から品質確認まで
- `infra-hearing` -> `infra-terraform`: 要件構造化からコード生成まで
- `design-ui_layout` -> `doc-ui_pattern`: UIレイアウト確定から画面単位の仕様書作成まで

まとめ
-------------------------

本プロジェクトには33件のカスタムプロンプトが用意されており、ドキュメント生成・品質チェック・設計・図表作成・タスク管理・レポート生成・インフラ運用など多岐にわたる作業をカバーしています。
プレフィックスによる目的分類と出力先の傾向を把握することで、目的のプロンプトを素早く見つけられます。
また、派生プロンプトの関係性やチェック系プロンプトとの組み合わせを活用することで、一貫性のある成果物生成と品質保証のサイクルを効率的に回せます。
